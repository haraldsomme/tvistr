# Ny flyt: brevet bygges før betaling — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The buyer answers every question that shapes the letter before paying and watches the letter grow beside the questions, with key parts redacted on the server; after payment the same layout shows the whole letter, the answers as editable rows and the decision picker as a dialog.

**Architecture:** The letter is built only on the server. `byggBrev` gains field tags (same text), a pure `sladd` hides parts of each paragraph, and two server actions answer the browser: `forhandsvis` (anyone, redacted, nothing stored) and `fulltBrev` (owner only, whole text). The browser keeps the unpaid answers in `localStorage` as an `Utkast` (the `Skjema` plus three check answers); `kjop` saves that `Skjema` as the case. The pages are rebuilt in the mockup's two-pane layout, reusing today's step components as question screens and as the paid page's rows.

**Tech Stack:** Next.js 16.3.7 App Router (server actions, `import "server-only"`), React 19, TypeScript, Drizzle on Neon, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-ny-flyt-design.md` (mockup: `docs/superpowers/specs/2026-10-21-ny-flyt-mockup.html`; open it in a browser, the bundled source is inside the file).

## Global Constraints

- Read the relevant guide in `node_modules/next/dist/docs/` before writing Next.js code (AGENTS.md).
- Work on a branch `ny-flyt`, not `master`.
- The argument and the choice of decision do not change: `evaluate`, `wsFactors`, `skriverResultat`, `lov.ts`, `src/lib/matching/`, `src/lib/vedtaksvalg/`, `finnVedtak`, `vurderSaken`'s result, `avstem`, Vipps, login, `laas`, `rensSkjema`, autosave. `brev.test.ts` snapshots must pass unchanged; never run Vitest with `-u`.
- Before payment no template sentence from `brev.ts`, no hidden text, no quote, link or case number reaches the browser. The whole letter goes only to the logged-in owner (`hentEgenSak`), with the locked fields from the case (`laas`).
- No model call before payment. No case is saved before `kjop`. `forhandsvis` stores nothing and logs no answers.
- Before/after split exactly as the spec's «Før og etter betaling» tables. Before payment: `l_tone` is «saklig», `l_date` today, `k_days` 14 (the defaults).
- An owner who already paid for the same car and faults is sent to that case; the answers just built are discarded, and the result screen says so first: «Du har alt et brev for denne bilen og feilen. Svarene du har fylt inn nå, blir ikke overført.»
- The purchase dialog (`src/app/deler/kjop.tsx`) keeps the consent box (angrerettloven § 22 n) and Vipps' own button inside it.
- Look from the mockup: background `#F3F5F8`, text `#0F1B2D`, accent `#17304F`, CTA `#F5B83D`, new-field mark `#FCE7A8`; Geist, Geist Mono, Source Serif 4 (already in `layout.tsx`); two panes from 960px, question column max 560px; bottom sheet with a peek bar below 960px. No «Fyll ut eksempel».
- Copy is Norwegian; code comments English, in the surrounding style. Price only through `PRIS`/`GRATIS`.

## Review Focus

- **Fast typing:** answers that change faster than the server answers must end with the letter for the latest answers, never an older one arriving late. Test in Task 4 (`sisteVinner`).
- **A returning visitor with today's `tvistr-sjekk`:** the flow opens with those answers carried over, not blank and not crashing. Test in Task 3 (`fraGammelSjekk`).
- **Preview fails** (network, rate limit): the last letter stays on screen with «Brevet oppdateres ikke akkurat nå. Prøver igjen …», and the next change retries. Test the action's refusal in Task 4; the UI in Task 5.
- **A forged `fulltBrev` call** (no session, someone else's case, an oversized or malformed `presedens`): refused, no letter text. Test in Task 4.
- **Abbreviations inside a sentence** («jf. § 29», «Org.nr. 923», «20. august», «reg.nr. EL») must not count as sentence ends in `sladd`. Test in Task 2.
